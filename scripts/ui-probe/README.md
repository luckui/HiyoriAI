# ui-probe：界面行为探测

渲染层没有单元测试。这个工具会启动**已构建的真实应用**，通过 Chrome DevTools 协议在渲染进程里点按钮、填表单，然后记录每一步观察到的结果，并收集页面异常和 `console.error`。

改渲染层之前先跑一次存为基准，改完再跑一次对比。只要结果一致，就说明用户能看到的行为没有变。

```bash
npm run build
npm run ui-probe -- settings --out before.json      # 改动前存基准
# …修改代码…
npm run build
npm run ui-probe -- settings --compare before.json  # 有差异时列出并以退出码 1 结束
```

## 场景

| 场景 | 覆盖内容 | 副作用 |
|---|---|---|
| `settings` | 各分区加载；未保存修改的标记、切换选项卡或关闭时的确认、放弃后还原；密码显示切换；平台面板切换；LLM 保存 | 会以原内容保存一次 LLM 配置 |
| `chat` | 折叠/展开时的窗口尺寸；对话列表；模式按钮循环一圈；在临时对话里真实发送一条消息（停止按钮、正在输入、情绪标签、输入框焦点）；删除临时对话 | **会调用当前的 LLM**；TTS 开启时会朗读回复 |

场景文件是在页面里执行的异步表达式（`scenarios/<名字>.probe.js`），返回 `{ 观察项: 值 }`。新增场景时，只记录"用户能看到的结果"（DOM 状态、窗口尺寸），不要依赖内部变量，这样才能跨重构对比。

## 注意

- 会用你本机的配置和数据启动应用，平台桥接（微信等）也会连上。
- 远程调试端口默认 9333，可用环境变量 `UI_PROBE_PORT` 修改。
- 结果依赖当时的环境，比如 TTS 服务是否已经启动、平台是否在线。所以对比要在同一台机器上、间隔不久地跑。
